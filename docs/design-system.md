# Дизайн-система Tirek · Architectural Intelligence

> Инженерная точность. Ясность процессов. Доверие к данным.
> «Мы не заменяем ОСИ. Мы становимся его техническим партнёром».

## 1. Концепция

Интерфейс построен как **чертёжный лист инженерной документации**, а не как шаблон SaaS-дашборда.
Архитектурный характер заложен в конструкцию, а не в декор:

| Приём | Где | Зачем |
| --- | --- | --- |
| Технический индекс раздела (`01 · Обзор · портфель объектов`) | шапки страниц, панели (`02`, `A`, `B`) | навигация по «листам» как в комплекте чертежей |
| Регистрационные метки в углах панелей (`registration`) | все `Card` | подпись системы, без лишних теней |
| Моноширинные метки `label-tech` | подписи полей, заголовки таблиц | технические обозначения, табличные цифры |
| Сетка-калька (`grid-blueprint`) | публичный сайт, схемы, пустые состояния | дозированно, никогда под текстом таблиц |
| Схема фасада со штампом «СХЕМА · НЕ В МАСШТАБЕ» | здание, дефект, кабинет ОСИ | пространственное понимание без ложной точности |

Два режима одного семейства:
- **Публичный сайт** — глубокий navy, выразительная линейная графика, прорисовка чертежа.
- **Рабочая платформа** — светлый холст `canvas`, плотность и читаемость; navy только в навигации.

## 2. Токены (`frontend/src/app/globals.css`)

### Цвет

| Токен | Значение | Применение |
| --- | --- | --- |
| `navy` | `#101D2C` | навигация, публичный сайт |
| `steel` | `#213D51` | вторичные тёмные поверхности, линии схем |
| `teal` | `#20A6A6` | акцент: фокус, маркеры, активные элементы. **Не для текста на светлом** (2.9:1) |
| `teal-strong` | `#147A7A` | текст-ссылки и кнопки на светлом (5.1:1) |
| `canvas` / `surface` / `mist` | `#F8FAFB` / `#FFF` / `#E9EEF1` | фон / панели / вторичные поверхности |
| `ink` / `muted` | `#192D3D` / `#647682` | основной текст / метаданные (4.7:1) |
| `faint` | `#8A99A4` | только декоративные подписи, не основной текст |

Семантика — базовый цвет для заливок и маркеров, `-ink` для текста (все ≥ 4.5:1):
`critical #B94E4E / #A23D3D`, `warning #C58B35 / #8A5F1F`, `healthy #27866E / #1F6C59`,
`info #258D96 / #1C6F77`, `unknown #7C8893 / #5B6772`.

Шкала риска: `r1` = critical, `r2` = warning, `r3` = `#4F7690` (стальной синий), `r4` = unknown.

### Типографика

- **Inter Variable** (`@fontsource-variable/inter`, кириллица, self-hosted) — интерфейс.
- **IBM Plex Mono** (`@fontsource/ibm-plex-mono`) — идентификаторы, метрики, технические метки.
- Цифры в метриках и таблицах — `tabular`. Заголовки: 22–26 px, `-0.015em`; дисплей сайта: 44–64 px, `-0.035em`.

### Геометрия, тени, движение

- Отступы — сетка 8 px с шагом 4 px (Tailwind spacing).
- Радиусы: `xs 2 · sm 4 · md 6 (кнопки, поля) · lg 8 (панели) · xl 12 (крупные контейнеры)`.
- Тени: `hairline` (по умолчанию), `panel` (выбранный сегмент), `overlay` (диалоги, подсказки). Без «парящих» карточек.
- Движение: `fast 150 ms` (обратная связь), `base 220 ms`, `slow 320 ms`; кривая `ease-precise`.
  Прорисовка чертежа — `draw-path` (2.4 s, только на публичных страницах и при первом показе схемы).
  `prefers-reduced-motion` отключает анимации; информация доступна без них.

## 3. Семантика: два независимых измерения

| Измерение | Компонент | Кодирование |
| --- | --- | --- |
| **Серьёзность** (экспертная категория R1–R4) | `RiskBadge`, `SeverityMeter` | цвет + форма иконки (восьмиугольник / треугольник / ромб / круг) + 4-сегментный индикатор + текст |
| **Статус процесса** | `StatusBadge` | нейтральный чип с точкой тона; никогда не заливается цветом риска |
| **Утверждённость** | `ApprovalTag` | «Утверждено» — сплошной; «Предварительно» — пунктир |

Предварительная серьёзность (оценка полевого специалиста) показывается **пунктиром** с «предв.» —
её нельзя спутать с утверждённой инженером категорией. Критический дефект может быть «В работе» — оба признака видны одновременно.

## 5. Схема здания (`BuildingElevation`)

- Геометрия строится **только из паспорта**: этажность × подъезды. Неизвестное — «неизвестно», заглушка нейтральна.
- Дефект размещается по **зоне** (кровля / фасад / подвал / инженерные системы) и подъезду из иерархии элементов,
  а не по координатам. Штамп листа: «СХЕМА · НЕ В МАСШТАБЕ · расположение по зонам».
- Инженерные системы без привязки к фасаду — в отдельной полосе под отметкой земли.
- Маркер: заливка = утверждённый риск; пунктирный контур = оценка не утверждена. Номер маркера = номер в списке.
- Доступность: каждый маркер фокусируется с клавиатуры, имеет `aria-label`; под схемой — полный список-эквивалент со ссылками.
- Технология — SVG: достаточно для задачи, без 3D-движка ради эффекта.

## 6. Адаптивность

| Ширина | Поведение |
| --- | --- |
| ≥ 1280 px | двухколоночные рабочие экраны, таблицы со всеми колонками |
| 1024–1279 | навигация-рельс, панели в одну-две колонки |
| < 1024 | навигация в выезжающем меню; вторичные колонки таблиц скрыты |
| < 640 (телефон) | чек-лист: закреплённый прогресс, разделы-чипы, нижняя панель отправки, камера через `capture` |

## 7. Чего избегаем

Сводные «индексы состояния» без методики · выдуманные результаты и отзывы · градиенты и glassmorphism ·
цвет как единственный носитель смысла · «цифровой двойник» без пространственных данных ·
текст `teal` на светлом фоне (контраст).

## 8. Публичный сайт

Секции A–I (`app/(public)/page.tsx`): hero со схемой фасада и выносками · проблема · процесс из 6 шагов ·
интеллект здания (реальные компоненты на данных с пометкой «демо») · жизненный цикл дефекта · план профилактики ·
разделение ответственности с ОСИ · структура отчёта (образец) · призыв к действию.
Контакт для CTA задаётся `NEXT_PUBLIC_CONTACT_EMAIL`; без него CTA ведёт на вход для партнёров.
